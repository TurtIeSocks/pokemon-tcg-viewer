# Mega Corpus — merging TCGdex + pokemontcg.io into one enriched catalog

**Date:** 2026-06-30
**Branch:** `feat/multilingual-catalog`
**Status:** Design approved, ready for implementation plan

## Problem

The `feat/multilingual-catalog` branch swapped the card-data source from
pokemontcg.io to TCGdex to gain localization (fr/de/es/it/pt names, attacks,
localized card art). The swap regressed several things that pokemontcg.io did
better, surfaced as seven owner complaints:

1. Some set logos are missing (present when sourced from pokemontcg.io).
2. Many holos no longer render the correct foil CSS.
3. The locale dropdown's coverage `%` doesn't tell the per-card story — picking
   Deutsch still shows many English cards with no per-card indication.
4. Locale isn't selectable from the card modal/page.
5. Card image quality feels worse than pokemontcg.io's.
6. Filter terminology should align with collector canon, and "All X" labels
   should be plural.
7. Subtypes lost granularity — pokemontcg.io carried richer multi-tag arrays.

## Empirical grounding (live API comparison, 2026-06-30)

Verified against live `api.tcgdex.net/v2/en` and `api.pokemontcg.io/v2`:

**Subtypes — the data is split, not lost (mostly).** TCGdex models the card's
real anatomy as separate typed fields (`stage`, `trainerType`, `energyType`,
`suffix`); pokemontcg.io lumps all of them into one `subtypes[]` bag.

| Card | ptcg.io `subtypes[]` | TCGdex typed fields | Verdict |
|---|---|---|---|
| Charizard (base1-4) | `["Stage 2"]` | `stage:"Stage2"` | Identical info |
| Trainer (swsh1-169) | `["Supporter"]` | `trainerType:"Supporter"` | Identical info |
| Item (swsh1-170) | `["Item"]` | `trainerType:"Item"` | Identical info |
| Pikachu&Zekrom-GX (sm9-33) | `["Basic","TAG TEAM","GX"]` | `stage:null` + `suffix:"TAG TEAM-GX"` | **ptcg.io richer** — drops "Basic", fuses TAG TEAM+GX |

So for ordinary cards TCGdex is lossless; for chase cards (GX/V/VMAX/ex/TAG TEAM)
it fuses mechanics into one `suffix` and sometimes nulls the base stage.
pokemontcg.io wins exactly on the expensive cards.

**Rarity — TCGdex is coarse and does not encode foil.**

| Card | ptcg.io rarity | TCGdex rarity | TCGdex `variants` |
|---|---|---|---|
| Charizard | `Rare Holo` | `Rare` | holo=true |
| Pika&Zekrom-GX | `Rare Holo GX` | `Ultra Rare` | holo=false, normal=true |
| Trainer | `Rare Holo` | `Holo Rare` | holo=true, rev=true |

Two findings drive the holo fix:
- TCGdex rarity (`"Rare"`, `"Ultra Rare"`) does not encode the foil; pokemontcg.io
  encodes tier+foil+mechanic in one string (`"Rare Holo GX"`), which is exactly
  the key the foil CSS tables (`rarity.ts:RARITY_CLASS`, `foil-assets.ts:RARITY_MAP`)
  expect.
- `variants.holo` is **not** a reliable foil signal: the foil GX card reports
  `holo:false, normal:true` (its foil is intrinsic to the only printing). So foil
  CSS cannot be driven from `variants.holo`.

**Each source is richer on a different axis** (the real "mega" thesis):
- TCGdex wins: localization, `variants_detailed` (1st-edition/shadowless/copyright
  print variants with stamps), live `pricing` (cardmarket + tcgplayer), `evolveFrom`.
- pokemontcg.io wins: multi-tag subtypes on chase cards, foil-encoding rarity vocab,
  lossless hires images, set logos for promo/edge sets, `level`, `rules`.

## Goal

Build the corpus as a **merge of both sources**: TCGdex as the encyclopedic,
localized base; pokemontcg.io overlaid to restore the richer English metadata.
"Most granular wins" when both vaguely offer the same field.

## Architecture

### Where the merge happens

The corpus is generated by a GitHub Action that already crawls TCGdex
(`scripts/build-corpus.ts`, two-phase crawl at `:269-381`). Add a **second crawl
of pokemontcg.io in the same Action**, then a merge phase that overlays ptcg.io
fields onto each TCGdex base card before gzip (`:403-411`).

No new join is needed: `src/lib/corpus/id-crosswalk.ts` already maps TCGdex card
id → pokemontcg.io id (via `set-crosswalk.json` + `tcgdexCardToPtcg()`, plus 31
hand-verified overrides in `ptcg-image-overrides.json`). The merge reuses it to
look up the ptcg.io record per TCGdex card.

```
GitHub Action (corpus build)
  ├─ Phase A: crawl TCGdex /v2/en  → CorpusCard[] base (existing)
  ├─ Phase B: crawl pokemontcg.io /v2/cards → ptcgById map (NEW)
  │            fields selected: rarity, subtypes, images, set.images
  ├─ Phase C: merge — for each base card, crosswalk → ptcg.io record,
  │            overlay the fields below (NEW)
  └─ Phase D: resolveFallbackImages → gzip → upload (existing)
```

**Resilience.** The ptcg.io crawl gets the same retry the TCGdex crawl needs
(known CI gotcha), plus a **keep-last-good** guard: if ptcg.io is unreachable or a
set returns empty, the merge is skipped for the affected cards (they keep their
TCGdex values) rather than blanking the overlay. A flaky upstream must never wipe
rarities mid-build. The build logs how many cards were overlaid vs skipped.

### Field overlay table (ptcg.io → TCGdex base, English base only)

The overlay touches **only the English base corpus**. The per-language i18n
overlays (`corpus/i18n/{fr,de,es,it,pt}/`) stay TCGdex-only.

| Field | Source of truth | Rule |
|---|---|---|
| `rarity` | **ptcg.io** | Overlay ptcg.io rarity where crosswalk hits. Language-invariant → fixes holo CSS for **all** languages at once. Fallback (miss): derive a foil-valid rarity from TCGdex `{rarity, suffix, variants_detailed}`. |
| `subtypes` | **ptcg.io** | Use ptcg.io's clean array where crosswalk hits; else the existing TCGdex assembly `[stage,trainerType,energyType,suffix]` (`build-corpus.ts:56-63`). |
| `imageUrl` / `imageUrlSmall` (EN) | **ptcg.io** | EN base: grid = ptcg.io small `.png`; modal/page = ptcg.io `_hires.png` (matches `main`). TCGdex is the fallback when ptcg.io lacks the card. |
| set `images.logo` / `images.symbol` | **ptcg.io** | Overlay where TCGdex is `undefined` (53/209 logos, 41 symbols missing — promos, McDonald's, trainer kits). |
| localized name / attacks / abilities | TCGdex | Unchanged — the whole reason for the swap. |
| `imageBase`, `dexId`, `variants`, `variants_detailed`, `types`, `stage`, `evolveFrom` | TCGdex | Kept. Non-EN images still derive from `imageBase` via `cardImage(card, lang)` (`card-image.ts:30`). |

**Non-English images are unaffected:** `cardImage()` already returns
`{CDN}/{lang}/{imageBase}/high.webp` for non-EN; only the EN baked URLs change to
prefer ptcg.io.

## Holo / foil fix (complaint #2)

Falls out of the rarity overlay: once each EN base card carries ptcg.io's rarity
string, `getRarityClass` (`rarity.ts:52`) and `getCssRarity` (`foil-assets.ts:23`)
receive the vocab they were always keyed for — holos render again across all
languages (rarity lives on the base card, shared by every overlay).

For the minority of cards the crosswalk misses (newer sets, ptcg.io gaps), add a
small TCGdex→foil derivation as fallback: map TCGdex coarse rarity + `suffix`
(GX/V/VMAX/ex → foil) + `variants_detailed` to a CSS-valid foil class, so an
unmatched card still gets a sensible foil instead of `holo-basic`.

## Subtypes facet — grouped, single control (complaints #6, #7)

Keep **one** `Subtypes` filter (no split into multiple facets), but render its
options in **grouped sections** using shadcn `SelectGroup` + `SelectLabel` —
already exported from `src/components/ui/select.tsx:179` (zero new dependencies).

The group of each value is canon and stable, seeded from TCGdex's typed-field
axes (which field a value lives in tells you its axis). Bake into a static dict;
classify the flat facet list at render. `set-facets.ts` stays unchanged (still
emits `sortedDistinct` subtypes); grouping is pure UI.

New sibling file (non-component export, per project convention):
`src/components/islands/subtype-groups.ts`

```ts
export type SubtypeGroup = "Stage" | "Mechanic" | "Trainer" | "Energy" | "Other";

// Seeded from TCGdex axes: stage→Stage, suffix→Mechanic, trainerType→Trainer,
// energyType→Energy. Extend as new vocab appears; unmapped falls to "Other".
export const SUBTYPE_GROUP: Record<string, SubtypeGroup> = {
  // Stage (rendered in evolution order, not alpha)
  Basic: "Stage", "Stage 1": "Stage", "Stage 2": "Stage", BREAK: "Stage",
  Restored: "Stage", MEGA: "Stage", "Level-Up": "Stage", Baby: "Stage",
  "V-UNION": "Stage",
  // Pokémon Mechanic
  ex: "Mechanic", EX: "Mechanic", GX: "Mechanic", V: "Mechanic",
  VMAX: "Mechanic", VSTAR: "Mechanic", Tera: "Mechanic", Radiant: "Mechanic",
  "TAG TEAM": "Mechanic", Prime: "Mechanic", LEGEND: "Mechanic", Star: "Mechanic",
  Shining: "Mechanic", Amazing: "Mechanic", Ancient: "Mechanic", Future: "Mechanic",
  "Single Strike": "Mechanic", "Rapid Strike": "Mechanic", "Fusion Strike": "Mechanic",
  // Trainer
  Item: "Trainer", Supporter: "Trainer", Stadium: "Trainer",
  "Pokémon Tool": "Trainer", "Technical Machine": "Trainer", "ACE SPEC": "Trainer",
  // Energy
  Special: "Energy",
};
```

Group order in the dropdown: **Stage → Pokémon Mechanic → Trainer → Energy →
Other**. Within Stage, evolution order; other groups alphabetical. An "All
Subtypes" item stays pinned at the top, ungrouped.

- **"Basic" collision** (Basic Pokémon vs Basic Energy): facets are computed
  per-page, so on a Pokémon page "Basic" means stage. Default `Basic → Stage`.
  `ponytail: single mapping, acceptable edge`.
- **Grouping applies to Subtypes only.** Rarity is a single linear tier axis;
  grouping it adds noise. Leave it flat.

### Terminology / labels

- Pluralize the "All X" labels: **All Subtypes / All Rarities / All Types / All
  Energy Types** (`FilterSelect` at `search-controls.tsx:73` builds `All ${label}`
  from singular labels — pluralize the labels).
- Keep the facet name **"Subtypes"** (pokemontcg.io's de-facto-canon umbrella;
  the individual values are all printed-card canon). Do **not** rename to "Stage"
  — that would shrink the facet's meaning and lose the mechanic tags.

## Locale UX (complaints #3, #4)

### #4 — Language control in the card modal/page

Mount `CardLanguageControl` (`src/components/islands/card-language-control.tsx`)
inside the card modal/page, bound to the **same** URL `lang` state the grid uses
(via the existing `useEnsureI18n()` / `useActiveI18n` lane), so a switch in the
modal persists when it closes. Today the control is only in `ResultsBar`.

Also replace the hardcoded `LANGUAGE_COVERAGE` record (`languages.ts:38`, drift-
prone) with the **real** coverage fraction computed at build time and written into
each `corpus/i18n/{lang}/meta.json`. The dropdown reads the live value.

### #3 — Per-card fallback indicator ("badge the fallbacks")

The signal already exists in the data: a card absent from the active language's
overlay (`namesById` membership) is being shown in English. No new build output —
expose membership as a per-card `isFallback(lang)` check in the i18n runtime.

UI treatment:
- **Grid tile:** when active `lang !== "en"` and the card is a fallback, show a
  small muted "EN" pill in a corner (compose the Liquid Glass system — frosted
  chip, `--ink-muted`, `motion-reduce` safe). Only the minority that fell back are
  badged, keeping the grid clean.
- **Card modal/page:** a one-line notice, e.g. "Shown in English — not available
  in Deutsch", near the language control.

## Out of scope / parked

- **Image delivery transform (complaint #5, the "middleground").** Parked by owner
  decision. For now replicate `main`'s ptcg.io behavior (EN: grid lowres `.png`,
  modal lowres + `_hires.png`). A Cloudflare `/cdn-cgi/image/` transform
  (`format=auto`, `quality~82`, width-capped) remains the future option but is not
  built here.

### Immediate follow-up roadmap (owner-confirmed 2026-06-30)

These are the **next two branches after this one ships**, in order — both
discovered during this design's API recon, both sourced from the TCGdex base
already in the corpus:

1. **`variants_detailed`** — surface TCGdex's per-printing variant data
   (1st-edition / shadowless / copyright-year, with `stamp` + `variantId`). Richer
   than anything pokemontcg.io carries; available on every TCGdex card. Tackle
   **directly after** the mega-corpus merge.
2. **Pricing** — TCGdex now serves `pricing.cardmarket` + `pricing.tcgplayer` live
   on every card (contradicts the "pricing dropped pending PriceCharting" note in
   memory). Free Vault-valuation win, no extra upstream. Tackle **after**
   `variants_detailed`.

## Testing

- **Merge unit tests** (`scripts/build-corpus.test.ts`): crosswalk hit overlays
  rarity/subtypes/images; crosswalk miss keeps TCGdex values; ptcg.io-down →
  keep-last-good (no blanking).
- **Foil regression:** the four empirical cards (base1-4, sm9-33, a VMAX, a
  Supporter) resolve to a non-`holo-basic` foil class after overlay.
- **Subtype grouping** (`subtype-groups.test.ts`): each canon value maps to its
  group; unknown → "Other"; "Basic" → "Stage".
- **Locale signal:** a card absent from an overlay reports `isFallback=true`;
  present → `false`. Tests must pre-seed the corpus runtime (no network — project
  rule).
- **No new network in tests.** Pre-seed `useCorpusRuntime.setState(...)` per the
  project's standing rule.

## Suggested phasing (for the implementation plan)

1. **Build pipeline** — ptcg.io crawl + merge overlay (rarity, subtypes, EN images,
   set logos) with keep-last-good. The data foundation.
2. **Holo fix** — verify rarity overlay restores foils; add crosswalk-miss
   derivation fallback.
3. **Subtypes grouping + terminology** — `SUBTYPE_GROUP` dict, grouped `Select`,
   pluralized labels.
4. **Locale UX** — modal language control, computed coverage, per-card "EN" badge.

Phases 2–4 are largely independent once Phase 1 lands.
