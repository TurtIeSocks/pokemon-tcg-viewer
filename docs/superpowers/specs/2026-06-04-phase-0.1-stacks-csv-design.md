# Phase 0.1 — Stacks + CSV Portability — Design

**Date:** 2026-06-04
**Status:** Approved design → next step `writing-plans`
**Roadmap parent:** `docs/superpowers/specs/2026-06-04-collector-roadmap-kill-list-design.md` (Phase 0, Trust & Portability — items 0.1 + 0.2)
**Working product name:** Cardstack (rename parked; see memory `project_rename_pending`).

## Goal

Make the collection **portable and migration-friendly** — the strongest user-acquisition wedge (steal users trapped in spreadsheets / TCG Collector / Pokellector) and the core of the "your collection survives us" trust thesis. Along the way, fix a model gap: bulk-identical cards shouldn't require N individual records.

Splits into two sequential sub-phases:
- **0.1a — The Stack model** (foundational data-model change + rename + provenance fields + migration).
- **0.1b — CSV import/export** (rides on the finalized model).

This ordering means **one** migration, **one** rename pass, and the schema is final before Supabase (0.4) ever mirrors it.

## Locked decisions

| Decision | Choice |
|---|---|
| Record model | A **Stack** = N identical physical cards (same card, variant, condition, grading, price, provenance) via a `quantity` field. Differentiated copies = separate stacks. |
| Terminology | Record = **Stack**; unit = **card** ("you own 10 cards across 2 stacks"). Rename `Copy*` → `Stack*`. |
| `pricePaid` semantics | **Per-unit** (total cost = `quantity × pricePaid`). |
| CSV row modes | **Both**: per-stack (compact, default) + per-copy (exploded, `quantity=1`). Import auto-detects either. |
| Sequencing | **0.1a → 0.1b.** |
| Split / merge | **Split required** in 0.1a; **auto-merge identical stacks deferred** to a fast-follow. |
| CSV parser | **papaparse** (vetted) over hand-rolling. |
| Matching | **Confidence-tiered**: auto-accept high-confidence, route the rest to a review queue. |
| First named adapters | **TCG Collector** + **Pokellector** (+ a universal column-mapping importer as baseline). |

## 0.1a — The Stack model

### Data model (`src/store/userland/types.ts`)

Rename `CollectionItem` → **`Stack`**; add `quantity`, `source`, `storageLocation`:

```ts
export interface Stack {
  id: string;              // uuid = future DB PK
  cardId: string;          // corpus FK
  quantity: number;        // ≥ 1, default 1 — count of identical cards in this stack
  acquiredAt: number;      // ms epoch; default add-time; editable
  createdAt: number;       // ms epoch; immutable
  label?: string | null;   // user name; null = derive from metadata
  pricePaid: number | null;// PER-UNIT; null = unknown (≠ 0)
  variant: string | null;  // printing key from corpus card.variants
  notes: string | null;
  condition: CardCondition | null;
  grading: CardGrading | null;        // null or COMPLETE { company, grade }
  source: string | null;              // NEW (0.2): seller / where acquired
  storageLocation: string | null;     // NEW (0.2): binder/box location
  isPrimary?: boolean;
}
```

- `EditableCopyFields` → **`EditableStackFields`** = `label, acquiredAt, pricePaid, variant, notes, condition, grading, quantity, source, storageLocation`.
- `NewCollectionItem` → **`NewStack`** = `{ cardId } & Partial<EditableStackFields>` (repo assigns id/createdAt, defaults `quantity:1`/`acquiredAt`, null-fills the rest).
- `CopyPatch` → **`StackPatch`** = `Partial<EditableStackFields & Pick<Stack,"isPrimary">>`.
- `UserDataSnapshot.schemaVersion: 1` → **`2`**; `collection: Stack[]` (array key `collection` kept — it's a collection *of stacks*).

### Migration v1 → v2 (`backup.ts` + repo hydration)

- On hydrate / import of v1 data: default `quantity = 1`, `source = null`, `storageLocation = null`.
- `isValidSnapshot` accepts **both** v1 and v2; `parseSnapshot` upgrades v1 → v2 in memory. **Old JSON backups must still restore.**
- All optional fields stay `null`, never `undefined` (IDB/JSON/SQL agreement — survives the Supabase migration).

### Counts (`src/store/userland/selectors.ts`)

Owned totals = **`sum(quantity)`** across stacks, not stack count. Audit: `useOwnedCountBySet`, any "copies owned" display, binder progress. `ownedCardIdSet` / `groupByCardId` unchanged (presence/grouping, not count).

### Form (`copy-edit-form.tsx` → `stack-edit-form.tsx`)

Add **quantity** input (number, min 1, default 1) + **source** + **storageLocation** text inputs. Empty → `null` at the persistence boundary (TanStack Form convention).

### Split (required)

`splitStack(stackId, count)`: `1 ≤ count < quantity`. Reduces the source stack's `quantity` by `count`, creates a sibling stack (same fields) with `quantity = count`, opens it for edit. UI affordance on the stack row/manager. Without split, a stack is a one-way trap (can't peel off a copy that later gets graded).

### Rename blast radius (mechanical → subagent-friendly)

`types.ts`, `repo.ts` / `idb-repo.ts` (method names), `userland-store.ts` (actions), `CardCollectionManager`, `stack-edit-form`, `bulk-add-menu`, `$card_.manage` route, **all tests**, and **CLAUDE.md** ("per-copy model" → "stack model"). Full `CollectionItem`→`Stack` rename (coherent over piecemeal).

## 0.1b — CSV import / export

### Canonical CSV schema (documented + versioned: `cardstack-csv v1`)

```
card_id, card_name, set_id, set_name, number, variant, quantity,
condition, grading_company, grading_grade, price_paid_unit,
acquired_at, source, storage_location, label, notes
```

- **Per-stack export** (default): one row per stack, `quantity = N`.
- **Per-copy export** (exploded): one row per physical card, `quantity = 1`.
- Carries **both** `card_id` (clean round-trip) **and** foreign-friendly identity (`set_name`/`number`/`card_name`) so the file re-imports in other tools and survives corpus-id changes.
- **Field formats:** `acquired_at` = ISO `YYYY-MM-DD` (parsed to/from ms epoch); `price_paid_unit` = plain decimal, empty → `null` (unknown, ≠ 0); `quantity` = integer ≥ 1; `grading_grade` = decimal; empty cells → `null`.
- Export: extend `backup.ts` with `toCsv(stacks, mode)` + `downloadCsv`; UI toggle for mode.

### Import pipeline

`parse → detect → map → match → preview → commit`

1. **Parse** — papaparse (handles quoted newlines, BOM, delimiter sniffing, ragged rows).
2. **Detect format** — sniff headers → choose adapter: `cardstack` (our own) · `tcg-collector` · `pokellector` · `unknown`.
3. **Map columns** — adapters are pre-mapped (zero-config). `unknown` → **column-mapping UI** (source column → our field via dropdowns); remember the mapping for reuse.
4. **Match card → `cardId` (confidence-tiered):**
   - valid `card_id` in corpus → **exact (1.0)**
   - `set_id|set_name` + `number` → **high**
   - fuzzy `card_name` + set → **medium**
   - `card_name` only → **low**
   - **Auto-accept high+; route medium / low / unmatched to a review queue** where the user searches-and-picks the correct card. (Report's "confidence, not false certainty" applied to import — the reliability differentiator.)
   - **Variant disambiguation:** foreign strings ("Reverse Holofoil", "Normal"…) → our `variant` keys via a per-adapter mapping table; ambiguous → default + flag for review.
5. **Preview / dry-run** — "X matched · Y need review · Z unmatched → will create N stacks (M cards)." **Nothing commits until confirm.**
6. **Commit** — additive via repo. **Dedup toggle** ("merge duplicates"): collapses rows sharing the dedup key (`cardId + variant + condition + grading + source + pricePaid + label`) — both duplicate rows *within the import* and a matching *pre-existing* stack — by **summing quantity** instead of creating parallel stacks. Off = every row becomes its own stack.
   - ⚠️ **Not idempotent re-import protection.** Re-importing the same file adds again (toggle on → it *sums into* the prior import = inflated quantities). The **preview/dry-run is the guard** — the user sees the delta before committing. Stable-key idempotent re-import would need a per-row import key (foreign id or row hash); out of scope for 0.1.

### Adapters (after the universal mapper)

- **TCG Collector** — highest fidelity (qty / condition / variant / graded present). Pre-mapped + variant table.
- **Pokellector** — higher volume, weaker variant data → expect more review-queue rows.
- A named adapter only adds value if that app exports a file; otherwise users fall back to the universal mapper. Maintain a documented "supported imports" list.

## Testing (Bun; pre-seed corpus per the no-network test rule)

- **Round-trip**: export → import → identity (both CSV modes + JSON).
- **Migration**: v1 snapshot → v2 (quantity defaults, null provenance); v1 backup still restores.
- **Counts**: `sum(quantity)` across set/binder progress.
- **Split**: quantity math + field copy + guards.
- **CSV parse**: quotes, embedded newlines, unicode, BOM, ragged rows.
- **Adapters**: TCG Collector + Pokellector column mapping + variant tables.
- **Matching**: each confidence tier; review-queue routing; dedup/merge.
- **Boundaries**: empty `pricePaid`/`source` → `null`, not `0`/`""`.

## Success criteria (roadmap top-5 metrics)

- **% rows auto-matched with no manual fix** (import reliability).
- **Lossless round-trip** (export→import is identity).
- **Time-to-first-import** (migration friction).

## Out of scope / deferred

- Auto-merge of identical stacks (fast-follow after split).
- Collectr / Dex adapters (app-locked; revisit if/when they expose exports).
- Multilingual card matching (depends on Phase 2 catalog).
- Live market pricing / valuation (Phase 4).
- Supabase sync of stacks (0.4 — but schema is finalized here so the mirror is clean).
